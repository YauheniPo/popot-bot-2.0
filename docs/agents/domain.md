# Domain Docs

## Before exploring

This repo uses a single-context layout. Read root `GLOSSARY.md` for vocabulary
and relevant architecture decision records in root `docs/adr/`.

If absent, proceed silently. `/domain-modeling` creates these files when terms
or decisions are resolved.

## Use the glossary's vocabulary

Use glossary terms consistently in code, tests, and written output. For a
missing term, check existing project terminology before recording a vocabulary
gap for `/domain-modeling`.

## Flag ADR conflicts

When a proposal contradicts an existing ADR, identify that ADR and explain why
the decision should be reconsidered before changing it.
