# AI/IT digest для Hermes cron

`ai_digest` — skill для сохранённой cron-задачи Hermes. Задача, созданная через
бота, задаёт имя, расписание и `deliver` в Telegram-топик; skill задаёт
процедуру подготовки результата. Ту же задачу можно запустить вручную командой
`/cron run <job_id>`. Отдельная команда `/ai_digest` и отдельный сервис не нужны.

## Режимы и результат

`daily` — выпуск релизов, новостей, моделей и практических заметок.
`weekly` — выпуск исследований, подкастов и бенчмарков. Окна и число
материалов задаются в [sources.json](scripts/sources.json). Недельный отбор включает по материалу из каждой
из трёх категорий, если в ней есть свежие данные. Режим указывается в prompt
задачи: `daily` по умолчанию или `--mode weekly`. Имя, время и адрес доставки
остаются в созданной через бота cron-задаче, не в `sources.json`.

1. `scripts/collect_news.py` читает ограниченный объём данных из источников,
   фильтрует по времени, объединяет дубли, ранжирует и собирает проверяемый
   JSON. Для выбранных обычных статей он пытается получить текст, для HN/Reddit
   — верхние комментарии. Частичные сбои попадают в `source_issues`.
2. Агент пишет по-русски объяснения для Junior, Senior и Manager. Факты
   ограничены собранными данными и ссылками; интерпретации помечаются. Выпуск
   показывает область доказательства: статью, аннотацию, описание подкаста,
   метаданные модели или результат бенчмарка. Описание подкаста не считается
   прослушанной записью, наблюдение Trending — датой релиза.
3. `scripts/finalize_digest.py --stage` проверяет структуру и ссылки для всех
   отобранных новостей, дополняет блок `## Source availability` недостающими
   идентификаторами и состояниями источников из собранного JSON и сохраняет
   подробный черновик в приватном состоянии. Отдельный временный Python-скрипт
   для исправления этого блока не нужен.
   Агент возвращает сводку и `NEWS_CARDS:<путь к raw JSON>`; cron отправляет
   сводку в свой `deliver`, а управляемое расширение доставки посылает каждую
   новость отдельной карточкой с кнопками `1`, `2`, `3`.
4. Нажатия обрабатывает тот же Telegram gateway. В `feedback.db` сохраняются
   пользователь, новость, выпуск и оценка; повторное нажатие до завершения
   меняет оценку. После оценки **всех** карточек `finalize_selected()` создаёт
   `digest-<run_id>.md` только из пунктов с оценкой `3` и их полных объяснений
   для Junior, Senior и Manager. Gateway отправляет файл в исходный топик.
   Если оценок `3` нет, файл сообщает об этом. После завершения оценки выпуска
   блокируются, чтобы архив не расходился с кнопками.

JSON, черновик, SQLite-оценки и журнал сборщика находятся в `$AI_DIGEST_STATE_DIR`
(на VPS по умолчанию `~/.hermes/ops/news/`), итоговый файл — в
`$AI_DIGEST_OUTPUT_DIR` (на VPS `~/workspace/digests/`). SQLite работает
локально, без отдельного сервиса. Если у установленных cron-задач `ai_digest`
один владелец, сборщик автоматически применяет его историю оценок к следующему
отбору; при нескольких владельцах не смешивает их оценки и оставляет общий
отбор. Сводка оценок доступна командой `python3
$AI_DIGEST_SKILL_DIR/scripts/feedback.py --stats`. Историю cron можно смотреть через `hermes cron runs
<job_id>` и `hermes cron doctor`. Содержимое источников считается недоверенным
вводом; сетевые URL проверяются на публичный адрес, соединение закрепляется за
проверенным IP против DNS rebinding: `collect_news.py` получает адреса через
`_public_addresses()`, и каждый HTTP(S) handler подключается к одному из тех же
проверенных `sockaddr`; повторного DNS lookup при connect нет. Единственное
исключение — явно сконфигурированный endpoint SearXNG на буквальном IP
`127.0.0.1`; результат поиска и редиректы всё равно проверяются как публичные
адреса. Для HTTPS TLS
проверка сохраняет исходное имя хоста. Сборщик подключается напрямую: `http_fetch`
использует `ProxyHandler({})`, поэтому `HTTP_PROXY`/`HTTPS_PROXY` не применяются.
IP-адреса внешних источников берутся из DNS системы и проверяются на публичную
маршрутизируемость; это предотвращает подключение к private адресам и DNS
rebinding между проверкой и connect, но не является статическим allowlist источников или защитой
от скомпрометированного системного DNS. Считайте это best-effort защитой и
дополняйте её исходящими сетевыми правилами VPS, ограничивающими доступ к
private/loopback сетям.
Реализация находится в `scripts/collect_news.py`; тест
`test_http_fetch_connects_to_the_validated_address_without_resolving_again` в
`scripts/test_collect_news.py` проверяет подключение по закреплённому адресу без
повторного DNS lookup.

## Включение для существующей задачи

После обычного deploy попросите Hermes через Telegram изменить сохранённую
задачу `ai_digest`: сохранить её расписание и исходный Telegram-топик, убрать
старые ограничения `--limit` из prompt и использовать лимит из `sources.json`.
Удалите из старого prompt требование `MEDIA:` и немедленного архива: новый
процесс заканчивается `NEWS_CARDS:`, а файл выпуска приходит после оценок.
Для карточек нужен один Telegram-адрес доставки и `origin.user_id` владельца
задачи; задача, созданная через Telegram, уже хранит его. Запустите задачу
вручную через `/cron run <job_id>`, проверьте новый `run_id` и оцените все
полученные карточки. Итоговый MD придёт после последней оценки. Если источники
дали меньше материалов, оценить нужно только фактически присланные карточки.
Ни имя, ни расписание, ни ID топика не нужно записывать в репозиторий.

## Покрытие источников

Ежедневно используются исходные IT-ленты, OpenAI News, Google AI, DeepMind,
Hugging Face Papers/Trending, блог Simon Willison и поиск по Anthropic News,
Meta AI Blog, TLDR AI и X-публикациям Karpathy, Simon Willison и swyx. Поиск
X, LinkedIn и названных сайтов зависит от уже установленного SearXNG и наличия
даты в его результате; пропуски отображаются в отчёте. Если прямой Reddit API
блокирует VPS, сборщик ищет публичные страницы сабреддита через тот же SearXNG
и отмечает источник как degraded. Такой fallback не получает комментарии Reddit.

Если `vps_web.searxng_url` пуст, Ansible направляет только AI digest на
управляемый SearXNG VPS по `http://127.0.0.1:<host_port>` при включённых
`host_admin` и `searxng`. Это не меняет общий backend поиска Hermes. Явно
заданный `vps_web.searxng_url` имеет приоритет. Коллектор разрешает loopback
только для этого настроенного SearXNG endpoint; адрес закрепляется при
подключении. Ссылки из результатов, переходы и все остальные источники по-прежнему
должны разрешаться только в публичные IP.

Недельный выпуск использует RSS Import AI, Interconnects, Latent Space и
Dwarkesh Podcast, OpenAI/DeepMind и Hugging Face Papers, поиск по The Batch и
alphaXiv, а также опубликованный JSON SWE-bench Verified. LMArena, Artificial
Analysis и Hugging Face Open LLM Leaderboard просматриваются через датированные
результаты поиска: живые баллы и их изменения этим способом не сравниваются.
SWE-bench даёт новые датированные результаты отправленных агентов, а не
изменение позиции без предыдущего снимка. Для подкастов анализируется описание
в RSS; расшифровка аудио не выполняется.

GitHub Trending и curated README Awesome Open Source AI и Awesome Jev помогают
находить инструменты и проекты. Для curated README коллектор сравнивает версии
до и после коммитов за окно дайджеста и выдаёт только добавленные или изменённые
записи с их тематическим разделом. Датированная таблица Recent Developments в
Awesome Jev также даёт исходную дату события и ссылку на первоисточник. Время
изменения README обозначает окно обновления каталога, а не дату выпуска
инструмента; каталог не считается newsletter-публикацией.

Правьте `scripts/sources.json` в репозитории и применяйте обычный Ansible
deploy. Поддержаны RSS/Atom, Hacker News, Reddit, arXiv, GitHub Trending,
curated README, открытые Hugging Face API, опубликованный JSON SWE-bench и
SearXNG. Пустой
или недоступный источник отображается в выпуске. Новые ключи, платные API,
Python-зависимости и внешние сервисы не требуются.

Параметры `window_hours` (1–720), `limit` (1–20) и `topic` можно уточнить в
prompt сохранённой задачи. `request_timeout_s`, размеры ответов и текстов
ограничивают сетевую работу и расход токенов. GitHub Trending фильтруется по
теме `artificial-intelligence` и добавляет язык, общее число звёзд и звёзды за
день как popularity-сигналы; это наблюдение, а не дата публикации или оценка
качества. Если Trending недоступен, fallback GitHub Search помечается как
degraded, а дата последнего push хранится отдельно от публикации.

## Локальная проверка без Telegram

```bash
python3 -m unittest hermes/skills/ai_digest/scripts/test_collect_news.py hermes/skills/ai_digest/scripts/test_finalize_digest.py
python3 hermes/skills/ai_digest/scripts/collect_news.py --state-dir /tmp/ai-digest-check --limit 2
python3 hermes/skills/ai_digest/scripts/collect_news.py --state-dir /tmp/ai-digest-check --mode weekly --limit 3
```

Последние две команды делают реальные сетевые запросы и печатают путь к JSON.
Код `3` означает отсутствие пригодных материалов; `2` — ошибку конфигурации
или сохранения. Отправка в Telegram проверяется только запуском на VPS после
deploy; локальные тесты не подтверждают доставку.
